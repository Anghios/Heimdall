# The diagram tool keeps your work, and draws a real topology

The Diagram Editor was audited end to end, then rebuilt around what the audit
found. If you have used it before, three things will be immediately different:
it no longer loses work, the network diagram it draws now says what talks to
what, and you can connect to a host by clicking it.

## Your work is no longer at risk

Pressing Ctrl+S inside the editor saved nothing. It had never saved anything.
The page hosting the editor treated your explicit save exactly like its
automatic one, and both did no more than hand the drawing back to Heimdall to
hold in memory. Ctrl+S now writes to disk.

F5 dropped the diagram. Browser shortcuts were left enabled inside the editor,
so refreshing reloaded the page and everything unsaved went with it. They are
off.

Closing a tab full of unsaved work closed it in silence. You are now asked, and
choosing Cancel keeps the tab exactly as it was.

A diagram opened from Network Cartography was written to the temporary folder
first, and the editor adopted that path, so Save wrote somewhere nobody chose.
Such a diagram now has no file behind it and the first save asks where to put
it.

Work in progress is kept on disk while you edit. The editor reported every
change but only ever held it in memory, so a crash took everything since the
last save with it. A draft is now written beside Heimdall's own data, removed as
soon as the document reaches its file, and offered back the next time you open
that diagram.

## The network diagram is a topology

An exported scan had no links in it. It drew a box per host, arranged them in
columns by role, and stopped there: a diagram of a network that never said what
talks to what.

Every host is now joined to its network segment, one segment per detected VLAN
or one for the scanned subnet, each showing its gateway. A host that is itself a
gateway is drawn as the centre of its segment rather than hanging off it. Shapes
follow the role: a cylinder for a database, a hexagon for routing equipment, a
cube for a hypervisor.

Host nodes carry the session their open ports call for. Right-click one, choose
Open session, and Heimdall opens the SSH, RDP, VNC or Telnet session without a
saved profile. It names the protocol and the destination first, because a
diagram file can come from anywhere and a link inside one is an instruction to
reach a machine.

A later scan can be merged into a diagram instead of replacing it. Your
positions, colours and every shape you added survive, the data is refreshed, and
a host the new scan no longer reports is kept and greyed out rather than
deleted.

## More of a tool

- New from template, with three starting points: a network segment, a three tier
  application and a flow chart.
- Recently opened diagrams are remembered and offered again.
- Printing.
- Export to SVG. The button existed for PNG only, and the code behind SVG would
  have written a file full of the characters of a data URI rather than a
  drawing.
- The toolbar gave up five buttons to a File menu. It carried fifteen and
  already scrolled sideways in French.

## In the cartography

Right-clicking a discovered host offers Open session, which connects without
saving anything, and Add to servers, which keeps it.

Add to servers never added a server. It asked Heimdall for a tool that does not
exist, so the click opened a tab reading `Tool: __ADD_SERVER__` and the host was
never saved. It now opens the ordinary Add Server dialog, filled in with the
address, the name the scan resolved and the session the open ports call for.

## Closing a tool says the right thing

Refusing to close a tool always produced the same sentence: the tool is busy and
cannot be closed right now. That is true of the tools that refuse while a scan
or an export is running. It was not true of the two that ask you something
first.

Cancelling the diagram editor's save prompt reported the tool as busy, a moment
after you were the reason. A note that could not be written to disk was reported
the same way, so the close was withheld and the failure that withheld it was
never named.

A tool now says why. If you declined, nothing is said, because you answered the
question a moment ago. If a note could not be saved, it says so, and says the
tab was left open.

## Security

The embedded draw.io was two years and seven major versions behind: the tree
shipped 24.8.6 while every manifest claimed 26.0.9. It is now 31.4.5, which
carries upstream's fixes for three defects reachable by opening a crafted
.drawio file: cross-site scripting through the GraphML importer, a tracking
beacon through a CSS filter bypass, and a permanent freeze on extreme
coordinates.

The editor could still call out. It is now loaded with draw.io's offline and
stealth switches, and the vendored page carries a content policy that keeps
every request on Heimdall's local host. Upstream's policy allowed any image host
and the diagrams.net endpoints.

The three surfaces that serve a local bundle, the diagram editor, the Markdown
editor and the VNC view, now expose their asset folder only to a document of
their own origin instead of to any origin. Each was driven under the stricter
setting before it shipped.

## In your language

The editor opens in French when Heimdall is in French. The Save and Open dialogs
and their filters, the exporter's own labels, and the diagram's own title all
come from the catalogue now.

The context menu was showing resource keys: it read "undo / cut" beside
draw.io's own translated entries, and nothing in the source looked wrong,
because the key is exactly what the underlying editor is asked for.

## A correction to an earlier note

The entry for 26 March says draw.io's dropdown menus cannot open inside
Heimdall's embedded browser, and that its controls only look interactive.
Measured against the current bundle and false: the editor's own context menu
opens, is translated and works. Heimdall disables it deliberately, because it
worked well enough to open over Heimdall's own menu and swallow the click meant
for it. Hiding draw.io's chrome remains the right call, but it is a decision
about having one command surface, not a workaround for a broken one.

## How this was checked

Three of the features in this release shipped written, tested and unreachable,
and none of that was visible from the test suite. The Open session entry was
always disabled, the context menu showed resource keys, and the draft recovery
was offered from a place the tool never passes through. Each was found by using
the application, and each is now covered by a check that asks whether a real
gesture reaches the code, not only whether the code is right.
