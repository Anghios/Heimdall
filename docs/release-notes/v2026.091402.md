# Crash evidence now survives an update

A maintenance release with one change, and it is worth explaining rather than
listing, because what it fixes is invisible until the day you need it.

When a Windows application crashes on a stack overflow, no error handler runs.
Nothing reaches the application log, and no crash file is written unless the
machine was configured in advance to save one, which a managed workstation often
forbids. What the .NET runtime does write, every time, is a short report on its
error stream: the sequence of calls that repeated, and how many times it repeated.
That is exactly what identifies the defect, and it costs a few hundred bytes.

Heimdall has no console, so that report goes nowhere by default. Starting the
application from a small script that redirects its error stream to a file is
enough to keep it. Until this release, that arrangement stopped working after the
first update: the relaunched application was given a new console, and the file
stopped receiving anything. Nothing announced it, because the environment the
launcher set up did survive the relaunch. Only the redirection was lost.

The relaunched application now inherits the streams of the session it replaces.

## Fixes

- The application relaunched after an update keeps the standard output and error
  streams of the session it replaces.
- The installer is still started the other way, which is what lets an update that
  needs administrator rights ask for consent.

## What this does not do

It does not redirect anything on its own, and the application cannot redirect its
own error stream either: the runtime decides where that stream points before the
application's own code runs. Keeping the report still requires starting Heimdall
through a script that redirects it. This release only stops an update from
throwing that arrangement away.

Nothing changes for anyone who does not set up such a redirection.
