# La trace d'un plantage survit désormais à une mise à jour

Une version de maintenance qui ne porte qu'un seul changement, et qui mérite une
explication plutôt qu'une ligne de liste, parce que ce qu'elle corrige reste
invisible jusqu'au jour où on en a besoin.

Quand une application Windows s'arrête sur un débordement de pile, aucun
gestionnaire d'erreur ne s'exécute. Rien n'atteint le journal de l'application, et
aucun fichier de plantage n'est écrit sauf si le poste a été configuré à l'avance
pour en enregistrer un, ce qu'un poste géré interdit souvent. Ce que le runtime
.NET écrit, lui, à chaque fois, est un rapport court sur son flux d'erreur : la
suite d'appels qui s'est répétée, et le nombre de répétitions. C'est exactement ce
qui identifie le défaut, et cela coûte quelques centaines d'octets.

Heimdall n'a pas de console, donc ce rapport ne va nulle part par défaut. Lancer
l'application depuis un petit script qui redirige son flux d'erreur vers un fichier
suffit à le conserver. Jusqu'à cette version, ce montage cessait de fonctionner
après la première mise à jour : l'application relancée recevait une console neuve,
et le fichier ne recevait plus rien. Rien ne le signalait, puisque l'environnement
mis en place par le lanceur, lui, survivait à la relance. Seule la redirection se
perdait.

Le relanceur rouvre désormais ce même fichier, en mode ajout, pour la session qui
remplace celle qu'il arrête. Rien de ce qui a été écrit avant la mise à jour n'est
perdu, et rien n'est transmis pour une session qui n'avait pas de tel fichier,
c'est-à-dire toute session démarrée normalement.

## Corrections

- Une session dont le flux d'erreur est un fichier continue d'y écrire après une
  mise à jour.
- Une session dont le flux d'erreur n'est pas un fichier se relance exactement comme
  avant.
- L'installeur reste démarré de l'autre manière, celle qui permet à une mise à jour
  nécessitant les droits d'administrateur de demander le consentement.

## Ce que cela ne fait pas

Cela ne redirige rien par soi-même, et l'application ne peut pas non plus rediriger
son propre flux d'erreur : le runtime décide où pointe ce flux avant que le code de
l'application ne s'exécute. Conserver le rapport suppose toujours de démarrer
Heimdall par un script qui le redirige. Cette version empêche seulement une mise à
jour de jeter ce montage.

Rien ne change pour qui ne met pas en place une telle redirection.
